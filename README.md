# Advanced Privacy Blocker 2.1.0

A Chromium Manifest V3 privacy extension upgraded from the supplied conventional blocker into an independent, layered **Ghostery-class** privacy tool. It is **not affiliated with, endorsed by, or a copy of Ghostery**.

The package implements the Ghostery-style capabilities that can be independently reproduced with public filter data and Chromium extension APIs. Proprietary Ghostery services, private datasets, community telemetry and Gecko-only DNS capabilities are not represented as completed features.

## Implemented capability set

### 1. Network and page filtering

- Feature-separated static DNR rulesets for advertisements, tracking, annoyances and known malware destinations.
- Approximately **455,000** packaged static network rules generated by `npm run build` from the enabled built-in subscriptions (EasyList, ABPindo, AdGuard Mobile Ads, EasyPrivacy, AdGuard Tracking Protection, AdGuard Annoyances, URLHaus Online, Phishing/Malvertising, Botnet C2, PUP/Adware, Spam TLDs and Dandelion Anti-Malware).
- Security rules (malware, phishing, malvertising, botnet C2, PUP/adware, spam TLDs — ~120,000) are emitted at the highest priority band, so they still apply when a site is trusted or a resource-type allowance is enabled.
- Regional coverage for Indonesian/Malay sites via ABPindo, including its cosmetic rules.
- Adaptive activation according to Chromium's available static-rule quota.
- Runtime subscriptions to built-in and user-supplied HTTP(S) filter lists.
- Direct custom filter editor for supported network and cosmetic syntax.
- Domain-scoped cosmetic filtering, exclusions and cosmetic exceptions.
- Broad allow-rule diagnostics to surface exceptions that may weaken protection.
- Per-feature switches without collapsing all protection into one master rule list.

### 2. Tracker intelligence and controls

- Local tracker classification by company, category and domain patterns.
- Per-page aggregation of detected and blocked tracker activity.
- Per-site individual tracker controls: **Default**, **Always block** or **Allow here**.
- Tracker override rules are scoped to subresources and do not whitelist top-level navigation.
- Tracker exceptions cannot outrank high-priority malware blocks.
- Exact matched-rule diagnostics where Chromium exposes `declarativeNetRequest.onRuleMatchedDebug`; observational fallback otherwise.

### 3. Anti-tracking and navigation protection

- Removal of common campaign and click identifiers, including `utm_*`, `gclid`, `fbclid`, `msclkid`, `ttclid`, `wbraid` and `gbraid`.
- Safer same-site handling: ambiguous parameters such as `ref_url` and `adid` are preserved on same-site navigation but removed in broader cross-site/third-party contexts.
- Known redirect-wrapper unwrapping for Google, Facebook, LinkedIn, DuckDuckGo, Bing and Reddit patterns.
- Global Privacy Control and Do Not Track JavaScript signals.
- Request-header GPC/DNT rules where Chromium accepts `modifyHeaders`, with automatic fallback to content signals if header rules fail.
- Search-result destination badges and link cleaning.

### 4. Consent and distraction controls

- Best-effort automatic rejection for common CMP layouts, including patterns used by OneTrust, Cookiebot, Didomi, Quantcast Choice, Usercentrics, TrustArc, Complianz, CookieYes, Osano and Iubenda.
- **Reject** and **Hide only** consent modes.
- Removal controls for social widgets, third-party sign-in prompts and app-install banners.
- Optional YouTube Shorts and social Reels suppression.
- Interactive **Zap an element** mode with persistent site-scoped selectors.
- Page-side **scriptlets** (MAIN world) that neutralize anti-adblock bait properties and right-click/selection blockers, toggleable and fail-safe per scriptlet.

### 4b. Loosening controls (for sites broken by strict filtering)

- Global resource-type allowances: **Allow images**, **Allow media**, **Allow fonts** — off by default.
- Per-site **Allow images on this site only**: permits every image request initiated by that site, including its third-party image CDN, which is what comic/manga readers typically use. Security rules still outrank it.
- Trusted-site exclusions manageable from both the popup and the options page.

### 5. Operational and resilience controls

- Trust a site for one hour, one day or permanently.
- Global timed pause and immediate resume.
- Extension action context menu for trust, resume, Zap and settings.
- Import/export of settings, trust entries, custom lists, tracker overrides, custom filters and Zap selectors.
- Per-list parser statistics, update status, global counters and dynamic-rule export.
- Remote-source outage retention: the last working rules for each failed source remain active while successful sources and valid local custom rules continue updating.
- Serialized state mutations for settings, trust entries, tracker overrides, custom filters, built-in list switches and persistent cosmetic rules.
- Filter download timeout, size and subscription-count limits.

## Protection-order model

The DNR priority model is intentionally layered:

1. Explicit global/site trust: highest priority and user-controlled.
2. Known malware blocks: priority `50,000`.
3. Privacy parameter sanitization: priority `3,000`.
4. GPC/DNT request headers: priority `2,500`.
5. Individual tracker allow/block decisions: priority `1,000`.
6. Ordinary packaged and subscription filtering rules.

This prevents an individual tracker exception from silently disabling known-malware protection.

## Boundaries that are not falsely claimed

- **No Ghostery TrackerDB parity:** this project uses a smaller curated local tracker catalog and public filter data.
- **No proprietary heuristic anonymization:** it performs deterministic URL/parameter sanitization, not Ghostery's private anti-tracking implementation.
- **No WhoTracks.Me contribution backend:** there is no custom browsing-history or tracker telemetry service in this package.
- **No Ghostery True User Agent/community breakage service:** no vendor-hosted community diagnosis or remote recommendation backend is reproduced.
- **No CNAME-cloaking unmasking on Chromium:** the required DNS visibility is unavailable to ordinary Chromium extensions.
- **No system-wide protection:** this is not a VPN, Tor client, DNS resolver, endpoint firewall or antivirus.
- **No universal consent guarantee:** custom, shadow-DOM, pay-or-consent and adversarial consent walls can evade selector-based automation.
- **No universal YouTube/server-side ad guarantee:** first-party and server-side ad insertion can be indistinguishable from content.

## Build

Node.js 18 or newer is required.

```bash
npm run build
npm test
```

`npm run build` downloads the enabled built-in subscriptions, converts them to
`declarativeNetRequest` rules, writes `rules/generated/` (feature-grouped ruleset
files, per-feature cosmetic files and `ruleset-metadata.json`), and rewrites the
manifest's static ruleset registry. The hand-maintained `rules/*.json` seeds and
the `backup` entry are preserved.

Rule generation requires network access; the source lists are fetched at build
time rather than vendored. Re-run the build whenever you want to refresh the
packaged baseline — between builds the runtime engine keeps subscriptions current
on its own schedule.

`npm test` runs the converter unit tests plus a service-worker smoke test that
loads `background.js` against a mocked `chrome.*` and exercises every message
handler, catching runtime breakage that syntax checks alone would miss.

## Install as an unpacked extension

```bash
git clone https://github.com/akrizary/AdvancedPrivacyBlocker.git
```

1. Open `chrome://extensions` (or the equivalent page in Edge/Brave).
2. Enable **Developer mode**.
3. Choose **Load unpacked**.
4. Select the folder containing `manifest.json`.
5. Pin the extension and review its default protections.

The repository ships the generated rulesets, so the extension loads without a
build step. Run `npm run build` (Node 18+) when you want to regenerate them from
current upstream lists.

Do not delete or move the folder while the extension is installed — Chromium
loads unpacked extensions directly from that path. Developer mode must stay
enabled for unpacked extensions to run.

## Permission rationale

- `declarativeNetRequest`: block, allow, redirect and modify eligible requests.
- `declarativeNetRequestFeedback`: local matched-rule diagnostics where Chromium permits them.
- `storage` / `unlimitedStorage`: settings, list metadata, custom filters, tracker reports and persistent selectors.
- `scripting`: register main-world privacy signals.
- `tabs`: current-site status, reload and popup-to-page Zap commands.
- `alarms`: list refresh and timed trust expiry.
- `contextMenus`: action-menu trust, resume, Zap and settings shortcuts.
- `<all_urls>`: filtering and page-level protection must operate on visited HTTP(S) sites and retrieve explicitly enabled lists.

## Privacy posture

The package has no account system, ad SDK or custom telemetry endpoint. Network access is used for enabled filter-list downloads and ordinary page traffic. A custom filter subscription is a privileged input: a hostile or poor-quality list can hide legitimate content, add overly broad exceptions or break websites.
